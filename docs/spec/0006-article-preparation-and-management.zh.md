# RFC 0006：公众号发稿准备与管理能力扩展

- 状态：提案；扩展方向已确认，页面能力和具体接口待验证。本文不代表功能已实现，也不授权真实账号写入。
- 作者：mpctl 维护者
- 创建日期：2026-10-03

## 1. 目标与交付边界

补齐单篇图文的发稿准备流程：

```text
选稿／新建 → 文章字段 → 正文与图片 → 封面 → 检查 → 显式保存 → 预览
```

正文继续使用本地 HTML，标题、作者、摘要独立处理。图片由 CLI 读取，通过 Nexus 原生二进制能力传给扩展，再由已验证的微信页面能力上传或选择。

本轮不包含发布、定时发布、撤回、删除、多图文编排、完整草稿搜索分页、运营数据或跨账号批处理。

通信、页面绑定和测试边界沿用 RFC [0001](./0001-communication-architecture.zh.md)、[0002](./0002-mp-extension-development-and-release-flow.zh.md)、[0003](./0003-nexus-main-world-editor-bridge.zh.md) 和 [0005](./0005-engineering-and-testing.zh.md)。本提案扩展 RFC [0004](./0004-article-and-assets-workflow.zh.md) 的正文工作流，不改变其 hash 检查、文件安全和“不隐含保存／发表”语义。

命令草案、运行时落点、任务依赖与停止条件见 [RFC 0007](./0007-article-preparation-implementation-plan.zh.md)。其具体接口仍需页面和依赖验证，不能把实施草案当成已实现命令。

## 3. 对象与接口原则

文章是操作对象，tab 是操作场所。一个图文组可含多篇文章，本轮仍要求唯一支持的单篇目标；组 ID、索引和本地文件名都不能代替文章身份。

文章引用只绑定当前运行时已校验的文档／路由。保存可能改变身份；实现必须核对原引用是否仍有效，必要时返回新定位，而不是复活旧绑定。

平台素材是平台认可的图片对象。外链图片能显示、HTML 能读回图片 URL，都不等于素材已上传或可作为封面。本地路径只由 CLI 解释，扩展只接收内容及必要元数据。

### 3.1 命令职责

下表划分职责，暂不固定命令名、参数或服务拆分。

| 任务 | 输入方向 | 结果方向 |
| --- | --- | --- |
| 读取字段 | 文章引用；需要时指定输出文件 | 实际字段值及修改所需版本 |
| 修改字段 | 文章引用、一组明确提供的字段、必要版本 | 下一步所需的版本或平台规范化结果 |
| 上传图片 | 本地图片路径 | 可继续选择／插入的平台素材定位 |
| 选择素材／设置封面 | 文章引用、明确素材 | 实际选择结果中的必要信息 |
| 检查 | 文章引用 | 阻塞项和可处理的警告；无问题时不附长说明 |
| 保存 | 文章引用、必要的状态条件 | 可确认的保存结果；身份变化时提供新定位 |
| 预览 | 文章引用；发送时明确接收目标 | 已确认的预览阶段或结果 |

字段按一组读取／修改，不增加 `set-title`、`set-author` 等每字段一个命令。JSON 字段文件可作为普通输入，不要求固定目录、manifest 或 sidecar。图片插入方式在核实页面能力后确定，不提前添加正文光标／选区协议。

root help 展示任务入口，分组 help 解释工作流，叶子 help 说明必要参数和副作用。操作输出只保留下一步需要的数据；正文、大量字段和图片走文件，不回显已知路径／引用，不附成功布尔值或固定提醒。失败使用错误码、必要事实和至多一条恢复指令。

## 4. 字段修改

读取当前编辑器的实际字段值，核实可见编辑控件、隐藏值和提交状态的关系。正文里的 `<h1>` 不自动成为文章标题。

- 未提供的字段保持原值；显式空值的清空语义按字段规定。
- 必填项、长度限制、规范化和摘要自动提取规则以当前页面为准。
- 写入后回读，核对平台实际接受的值；无法确认时保留未知结果。
- 修改前再检查目标和字段版本，拒绝覆盖已检测到的外部修改。

`bodyHash` 只保护正文。字段／封面的并发检查需要独立确定读取范围和版本语义，不能借用正文 hash，也不宣称页面读后写是原子 CAS。

多字段修改没有平台原子事务保证。全部输入先校验；执行中途失败时，只报告已确认修改的字段及仍未知的部分，不能宣称全部未写入。不要自动重试整批或回滚覆盖用户修改。

## 5. 图片与封面

### 5.1 采用 Nexus 二进制传输

已确认采用新版 Nexus 的 RPC 二进制能力，不另建上传 HTTP 通道或 mpctl 分片协议。

```text
本地图片
→ CLI 读取并校验
→ Nexus RPC 参数：Blob + 必要元数据
→ IPC → broker Relay → WebSocket → 扩展
→ 已核实的页面上传能力
→ 平台素材定位
→ 显式插入正文／选择封面
```

优先用 `Blob` 承载图片内容和 MIME；适配边界需要字节视图时使用 `Uint8Array`。名称等必要元数据单独传递，不假定 `File` 的文件名能跨运行时保留。broker 只 Relay，不建立图片仓库、不解释本地路径、不二次编码业务图片。

Nexus 上游说明：

- 普通 RPC 参数／返回值支持 `Blob`、`ArrayBuffer`、`Uint8Array` 和 Node `Buffer`，也支持嵌套于受支持容器。
- Blob 保留内容和 MIME；Buffer／字节视图恢复为只含可见字节的 `Uint8Array`。传输不提供零拷贝或共享对象身份。
- 框架透明分帧和重组。该版本默认单帧 64 KiB、单消息硬上限 16 MiB、每个 Endpoint runtime 聚合缓冲预算 64 MiB。

这些是框架消息限制，不是微信图片限制。可接受图片大小必须同时满足平台规则、各跳编码后的消息上限和 mpctl 的内存预算；不能承诺恰好 16 MiB 的文件可传。业务不把图片转成 base64／JSON 数字数组，不把二进制打印到 stdout、日志或 agent context。

实施基线锁定 Core `2.0.0-alpha.1`；工作区已固定升级到 `2.0.0-alpha.2`，配套适配器版本见 RFC 0007。IPC／Relay／WS、后台／content Chrome 与 MAIN／ISOLATED 页面桥各段均已验证 100 KiB Blob RPC 的字节、MIME 和嵌套内容；这不是一个完整业务上传调用，也不证明平台上传成功或产品大小上限。

如果上传必须在 content／MAIN 执行，只把图片继续传到真正需要它的上下文，并验证对应 Chrome／页面桥路径。不要因为链路已有 MAIN 就默认让所有图片经过 MAIN；也不要把临时 Blob URL 当成跨进程素材身份。

### 5.2 平台上传与选择

Nexus 将图片送到扩展，不负责微信素材上传。页面上传成功、素材可用于正文／封面、文章已选中素材，分别需要可观察证据。

上传只产生素材；插入正文和设置封面是显式动作，随后回读当前文章确认。既有素材可直接选择，不能为了选择而重复上传。封面裁切和尺寸要求按真实控件确定，不从正文图尺寸推断。

文件不存在、内容无效或超限时，在派发前失败。调用已派发后发生超时／断线，不能据此判断平台没有产生素材；结果未知时不自动重复上传。传输成功也不等于微信上传成功。

本轮不建立素材去重仓库，也不处理素材库批量删除或跨账号复用。

## 6. 检查、保存与预览

**检查**只读核对目标、编辑器状态、已证实的必填字段和素材。它不发保存／预览请求，不保证检查后内容不变，也不保证审核或发布通过。

**保存（2026-10-13 用户决定，覆盖旧重开验收要求）**是调用者显式请求的独立动作。正文、字段和封面修改不自动保存。派发前保留精确目标、登录和三个当前 hash 检查；一次原生手动保存、新增历史确认及自有面板清理结束后，返回 settled/confirmed/result.ok，persistence unverified。不刷新列表、不重载编辑页、不做 canonical／漂移／新页三 hash 核验，不另建 verify 命令。原生未结束或清理未知仍不能成功，旧未决记录不解锁。原引用不会因 SAVE 自动失效；历史云端回读证据保持其原有含义，不成为当前命令职责。

**预览**区分页面查看与发送到微信。发送目标必须显式提供，不默认联系人或上次目标。请求已发起、平台已接受、预览已送达按证据分别报告；无法确认送达时不宣称已送达，也不重复发送。预览不发表文章。

## 7. 实施顺序与验收

| 阶段 | 交付 | 验收门槛 |
| --- | --- | --- |
| A：只读核实 | 字段读取；上传、保存和预览入口／结果观察 | 真实页面的脱敏事实、精确目标判据；既有稿只读 |
| B：字段编辑 | 一组字段修改与回读 | 隔离回归；授权测试稿的输入／清空／回读、冲突、部分修改和失效路径 |
| C：二进制与图片 | Nexus 升级、图片传输、上传／选择、封面 | 实际跨 IPC／WS／Chrome（需要时 MAIN）的字节一致性、MIME／元数据、超限与断线；另行证明微信素材可用及目标正确 |
| D：检查与保存 | 只读检查、显式保存与原生结果核对 | 原生确认／cleanup／零后续导航；云端重开不属当前 SAVE，真实保存另行授权 |
| E：预览 | 已核实的页面预览或明确目标发送 | 无发布副作用、请求／送达区分、未知结果不重发 |

每阶段沿用 typed Result：外部 API 和转换失败在接入处成为 Err，内部显式组合；清理和异步回调的 Err 必须被处理。二进制参数保留 Nexus 支持的值类型，结果遵循服务 codec；不要经过只支持 JSON 的业务中转而丢失 Blob。

各阶段保留正文 hash、文章身份、登录／路由、取消／清理和输入文件安全回归。隔离端到端走实际 CLI → broker → 扩展 → 所需页面上下文，不能 mock 掉声称验证的边界。特别测试多跳二进制经过 Relay 后的内容一致性、消息超限拒绝及未知上传不重放；性能与并发上限用实测确定。

协议变化要处理组件兼容和实际加载状态。热更新后的 metadata 不能证明存量服务已替换；完整加载后再验收，旧调用不重放。

真实微信验收单独记录账号／目标授权与观察范围。读取已有稿不授权修改、上传、保存或发送预览；凭据、认证 URL、动态引用和正文不得进入公开报告。

当前用户已明确授权为完成生产验证而使用一篇专用新稿，现有稿件仍只读、不发表／删除／发送联系人预览。P1 在该新稿上已验证作者／摘要修改、清空、Unicode、过期 hash 拒绝和正文隔离；对应 `tmp/reports/preparation-production-P1.md`。后续沿同一 private checkpoint 推进，不重复 new。该阶段未保存，不能据此宣称云端持久化。
